MINGGU 15 Materi perkuliahan

Progress Project – Bagian 1

Paruh terakhir semester dipakai untuk membangun final project. Pertemuan ini menetapkan cara kerja tim, alur Git, dan target integrasi yang harus tercapai pada progress pertama.

Tujuan pembelajaran

  • Menyusun rencana kerja project beserta pembagian tugas tim.
  • Menerapkan alur kerja Git dengan branch dan pull request.
  • Mengintegrasikan antarmuka dengan lapisan data dan API.
  • Menulis dokumentasi project yang memadai.
  • Melakukan pengujian dasar pada fitur yang sudah selesai.

Ketentuan final project

AspekKetentuan
AnggotaKelompok 3 sampai 4 orang
TemaBebas, harus disetujui dosen pengampu
Teknologi wajibFlutter, state management, REST API atau basis data lokal
PengumpulanRepository GitHub kelompok dengan riwayat commit seluruh anggota
Bobot40 persen nilai akhir, dinilai pada Minggu 15 dan 16

Requirement minimum aplikasi

  • Minimal enam halaman dengan navigasi yang berfungsi.
  • Pengelolaan state memakai Provider atau BLoC, bukan hanya setState.
  • Integrasi dengan REST API atau penyimpanan lokal SQLite, boleh keduanya.
  • Penanganan kondisi memuat, kosong, dan gagal pada setiap halaman yang mengambil data.
  • Antarmuka konsisten dan tidak mengalami overflow pada layar 360 piksel.
  • Berkas README yang lengkap beserta tangkapan layar.

Alur kerja Git untuk tim

terminal
# Satu orang membuat repository, anggota lain melakukan clone
git clone https://github.com/kelompok/nama-project.git
cd nama-project

# Setiap fitur dikerjakan pada branch terpisah
git checkout -b fitur/halaman-login

# Commit kecil dan sering, dengan pesan yang deskriptif
git add lib/pages/login_page.dart
git commit -m "feat: tambah form login beserta validasi"

# Ambil pembaruan dari main sebelum mengirim perubahan
git checkout main
git pull origin main
git checkout fitur/halaman-login
git merge main

# Unggah dan ajukan pull request
git push -u origin fitur/halaman-login
Awalan commitDipakai untukContoh
feat:Fitur barufeat: tambah halaman detail produk
fix:Perbaikan bugfix: atasi overflow pada kartu produk
refactor:Perapian kode tanpa ubah perilakurefactor: pisahkan widget kartu
docs:Dokumentasidocs: lengkapi README instalasi
style:Format dan penulisanstyle: rapikan indentasi
test:Pengujiantest: tambah unit test repository

Jangan pernah melakukan commit langsung ke branch main setelah pekerjaan dibagi. Satu konflik yang tidak tertangani pada main bisa menghentikan seluruh anggota tim sekaligus.

Menangani konflik

terminal
# Ketika muncul konflik saat merge
git status                       # lihat berkas yang bermasalah
# Buka berkas, cari penanda <<<<<<< ======= >>>>>>>
# Pilih atau gabungkan kode yang benar, hapus seluruh penanda

git add lib/pages/beranda.dart
git commit -m "merge: selesaikan konflik pada halaman beranda"

Praktikum

Praktikum 1 — Menyiapkan repository tim
  • Buat repository kelompok dan undang seluruh anggota sebagai kolaborator.
  • Lindungi branch main agar hanya menerima pull request.
  • Buat papan tugas sederhana memakai GitHub Issues atau Projects.
Praktikum 2 — Simulasi konflik
  • Dua anggota mengubah baris yang sama pada berkas yang sama.
  • Selesaikan konflik bersama-sama dan catat langkahnya.
  • Pastikan aplikasi tetap berjalan setelah konflik terselesaikan.
Praktikum 3 — Integrasi pertama
  • Gabungkan halaman yang dikerjakan tiap anggota ke dalam satu aplikasi.
  • Sambungkan minimal satu halaman dengan lapisan data.
  • Jalankan flutter analyze dan bereskan seluruh peringatan.

Tugas

Laporan progress 1

Kumpulkan dokumen maksimal empat halaman berisi deskripsi aplikasi, wireframe seluruh halaman, pembagian tugas beserta bukti commit tiap anggota, daftar fitur yang sudah selesai dan yang masih dikerjakan, serta kendala yang dihadapi. Sertakan tautan repository dan minimal enam tangkapan layar.
