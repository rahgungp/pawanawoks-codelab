MINGGU 16 Materi perkuliahan

Progress Project Bagian 2 & Final Project Expo

Pertemuan penutup menggabungkan progress kedua dan Final Project Expo. Aplikasi diselesaikan, diuji, dioptimasi, didokumentasikan, lalu dipresentasikan dan didemonstrasikan sebagai penilaian akhir semester.

Tujuan pembelajaran

  • Menyelesaikan seluruh fitur dan memperbaiki bug yang tersisa.
  • Melakukan pengujian menyeluruh pada berbagai kondisi perangkat.
  • Mengoptimasi performa dan ukuran aplikasi.
  • Menyusun dokumentasi akhir dan membangun berkas rilis.
  • Mempresentasikan serta mendemonstrasikan aplikasi secara profesional.

Penyelesaian dan pengujian

Minggu terakhir bukan waktu menambah fitur baru. Prioritaskan menstabilkan yang sudah ada: perbaiki bug, rapikan alur yang membingungkan, dan pastikan tidak ada layar yang membuat pengguna buntu.

Jenis pengujianYang diperiksaCara
FungsionalSeluruh fitur berjalan sesuai rancanganTelusuri setiap alur secara manual
AntarmukaTidak ada overflow, teks terbaca, sentuhan mudahUji pada layar 360 piksel dan tablet
Kondisi ekstremData kosong, teks sangat panjang, koneksi terputusSengaja ciptakan kondisinya
PerformaGulir mulus, tanpa jeda mencolokFlutter DevTools, mode profil
RegresiPerbaikan tidak merusak fitur lainJalankan ulang skenario uji utama

Kesalahan yang paling sering ditemukan saat demo

  • Aplikasi berhenti mendadak ketika data kosong karena pemakaian tanda seru pada nilai null.
  • Teks panjang merusak kartu karena overflow belum diatur.
  • Layar putih tanpa penjelasan saat internet mati.
  • Tombol kembali membawa pengguna ke halaman login setelah berhasil masuk.
  • Aplikasi tidak dapat dipasang di perangkat penguji karena APK belum dibuat.

Optimasi

dart
// Pakai const agar widget statis tidak dibangun ulang
const SizedBox(height: 16)

// Bangun hanya item yang terlihat
ListView.builder(itemCount: data.length, itemBuilder: ...)

// Simpan gambar jaringan ke cache
CachedNetworkImage(imageUrl: url, placeholder: (c, u) => const CircularProgressIndicator())

// Batasi rebuild pada bagian yang benar-benar berubah
Consumer<KeranjangModel>(builder: (context, model, child) => Text('${model.jumlah}'))
terminal
# Analisis statis dan format kode
flutter analyze
dart format lib/

# Menjalankan pengujian
flutter test

# Membangun berkas rilis
flutter build apk --release
flutter build apk --split-per-abi     # ukuran lebih kecil per arsitektur
flutter build appbundle --release

# Memeriksa ukuran aplikasi
flutter build apk --analyze-size

Bangun dan pasang APK rilis di perangkat yang bukan milik Anda paling lambat satu hari sebelum expo. Masalah yang hanya muncul pada mode rilis, seperti aset yang tidak ikut terbundel, akan terlambat ditemukan bila diuji pada hari H.

Dokumentasi akhir

  • README lengkap — deskripsi, fitur, teknologi, cara menjalankan, anggota tim, dan tangkapan layar.
  • Laporan akhir PDF — latar belakang, rancangan, arsitektur, implementasi, pengujian, dan kesimpulan.
  • Diagram — alur aplikasi, struktur folder, dan skema basis data.
  • Tangkapan layar — minimal delapan gambar yang mewakili seluruh fitur utama.
  • Video demo — 3 sampai 5 menit, sebagai cadangan bila demo langsung bermasalah.

Kerangka presentasi

  1. Judul, nama aplikasi, dan anggota kelompok.
  2. Masalah yang diselesaikan beserta target penggunanya.
  3. Fitur utama, maksimal lima poin.
  4. Arsitektur dan teknologi yang dipakai, disertai diagram.
  5. Demonstrasi aplikasi secara langsung.
  6. Tantangan teknis dan cara kelompok mengatasinya.
  7. Rencana pengembangan berikutnya dan penutup.

Jangan membacakan kode baris demi baris saat presentasi. Tunjukkan aplikasi bekerja, lalu jelaskan satu keputusan teknis yang paling menarik dari project kalian.
