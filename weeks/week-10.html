Dasar State Management

Ketika aplikasi bertambah besar, pertanyaan utamanya berubah dari bagaimana menampilkan data menjadi di mana data itu sebaiknya disimpan. Pertemuan ini membahas pengelolaan state dari yang paling sederhana sampai penggunaan Provider.

Dasar State Management

Lihat materi yang sudah dibuka

Tujuan pembelajaran

  • Menjelaskan apa itu state dan membedakan state lokal dengan state bersama.
  • Menggunakan setState secara tepat dan efisien.
  • Menerapkan lifting state up untuk berbagi data antar widget.
  • Memahami siklus hidup StatefulWidget dari initState sampai dispose.
  • Menggunakan Provider dan ChangeNotifier untuk state yang dipakai lintas halaman.

Apa itu state

State adalah data yang dapat berubah selama aplikasi berjalan dan memengaruhi tampilan. Nama pengguna yang sedang masuk, isi keranjang belanja, dan status pemuatan semuanya adalah state.

Jenis stateCakupanContohSolusi yang sesuai
Ephemeral / lokalSatu widgetIndeks tab aktif, teks di TextFieldsetState
App stateBanyak halamanData pengguna, keranjang, temaProvider atau BLoC
PersistentMelewati sesi aplikasiPreferensi, token, riwayatSharedPreferences, SQLite

Mulailah selalu dari setState. Naikkan ke Provider hanya ketika data yang sama benar-benar dibutuhkan oleh widget yang berjauhan dalam pohon. Memakai solusi berat sejak awal justru menambah kerumitan tanpa manfaat.

Siklus hidup StatefulWidget

MethodDipanggil saatDipakai untuk
initStateSekali, sebelum build pertamaInisialisasi controller, memuat data awal
buildSetiap kali perlu menggambar ulangMenyusun widget, hindari operasi berat
didUpdateWidgetKetika induk mengirim data baruMenyesuaikan diri dengan data baru
setStateDipanggil manualMenandai state berubah dan meminta build ulang
disposeKetika widget dilepasMelepas controller, listener, dan stream
dart
class _FormPencarianState extends State<FormPencarian> {
  late final TextEditingController _controller;
  String _kataKunci = '';

  @override
  void initState() {
    super.initState();
    _controller = TextEditingController();
    _controller.addListener(() {
      setState(() => _kataKunci = _controller.text);
    });
  }

  @override
  void dispose() {
    _controller.dispose();   // wajib, mencegah kebocoran memori
    super.dispose();
  }

  @override
  Widget build(BuildContext context) {
    return Column(
      children: [
        TextField(
          controller: _controller,
          decoration: const InputDecoration(hintText: 'Cari materi...'),
        ),
        Text('Mencari: $_kataKunci'),
      ],
    );
  }
}

Lifting state up

Ketika dua widget bersaudara membutuhkan data yang sama, pindahkan data itu ke induk terdekat, lalu turunkan nilainya sebagai properti dan aksinya sebagai callback.

dart
class HalamanKeranjang extends StatefulWidget {
  const HalamanKeranjang({super.key});

  @override
  State<HalamanKeranjang> createState() => _HalamanKeranjangState();
}

class _HalamanKeranjangState extends State<HalamanKeranjang> {
  final List<String> _item = [];

  void _tambah(String nama) => setState(() => _item.add(nama));
  void _hapus(int index) => setState(() => _item.removeAt(index));

  @override
  Widget build(BuildContext context) {
    return Column(
      children: [
        // anak menerima aksi, bukan menyimpan data
        DaftarProduk(onTambah: _tambah),
        RingkasanKeranjang(item: _item, onHapus: _hapus),
      ],
    );
  }
}

Bila data harus diturunkan melewati lebih dari tiga tingkat widget, itu tanda kuat bahwa saatnya berpindah ke Provider.

Provider dan ChangeNotifier

terminal
flutter pub add provider
lib/models/keranjang_model.dart
import 'package:flutter/foundation.dart';

class KeranjangModel extends ChangeNotifier {
  final List<String> _item = [];

  List<String> get item => List.unmodifiable(_item);
  int get jumlah => _item.length;

  void tambah(String nama) {
    _item.add(nama);
    notifyListeners();   // memberi tahu seluruh widget yang mendengarkan
  }

  void hapus(String nama) {
    _item.remove(nama);
    notifyListeners();
  }
}
dart
import 'package:provider/provider.dart';

void main() {
  runApp(
    ChangeNotifierProvider(
      create: (context) => KeranjangModel(),
      child: const MyApp(),
    ),
  );
}

// Membaca data dan ikut membangun ulang saat berubah
class BadgeKeranjang extends StatelessWidget {
  const BadgeKeranjang({super.key});

  @override
  Widget build(BuildContext context) {
    final jumlah = context.watch<KeranjangModel>().jumlah;
    return Badge(label: Text('$jumlah'), child: const Icon(Icons.shopping_cart));
  }
}

// Memanggil aksi tanpa ikut membangun ulang
ElevatedButton(
  onPressed: () => context.read<KeranjangModel>().tambah('Buku Flutter'),
  child: const Text('Tambah ke keranjang'),
)

// Membangun ulang hanya bagian tertentu
Consumer<KeranjangModel>(
  builder: (context, keranjang, child) => Text('Total: ${keranjang.jumlah} item'),
)

Memanggil context.watch di dalam callback tombol menyebabkan error. Aturan praktisnya: watch untuk membaca di build, read untuk memicu aksi.

Praktikum

Praktikum 1 — Penghitung dengan setState
  • Buat penghitung dengan tombol tambah, kurang, dan reset.
  • Cegah nilai turun di bawah nol.
  • Tambahkan riwayat sepuluh perubahan terakhir.
Praktikum 2 — Lifting state up
  • Buat dua widget bersaudara: daftar produk dan ringkasan keranjang.
  • Pindahkan data keranjang ke widget induk.
  • Pastikan penambahan item dari daftar langsung terlihat pada ringkasan.
Praktikum 3 — Provider lintas halaman
  • Ubah praktikum kedua agar memakai ChangeNotifierProvider.
  • Tampilkan jumlah item pada AppBar di seluruh halaman aplikasi.
  • Tambahkan pengaturan tema terang dan gelap yang juga dikelola Provider.
